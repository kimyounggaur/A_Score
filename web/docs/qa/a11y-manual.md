# 접근성 QA 기록

## 판정 원칙

- 자동 검사와 사람의 수동 점검을 분리해 기록한다.
- `통과`는 현재 프로덕션 빌드를 Playwright Chromium으로 실제 실행해 확인한 항목에만 사용한다.
- 키보드 자동 검사는 실제 `Tab`, `Shift+Tab`, `Enter`, `Space`, `Escape` 입력을 사용하지만, 사람의 시각적 포커스 확인이나 스크린리더 점검을 대신하지 않는다.
- axe 통과는 자동으로 탐지 가능한 위반이 없다는 뜻이다. 대체 텍스트의 문맥 적합성, 읽기 순서, 안내 문구의 이해 가능성은 별도의 사람 검토가 필요하다.
- 여러 뷰포트의 가로 넘침 검사는 리플로우 회귀의 대리 지표일 뿐이며, 브라우저의 실제 200% 확대 점검을 대신하지 않는다.
- 확인하지 않은 항목은 `미실시`, 문제가 있으면 `실패`로 남기고 재현 경로와 조치를 적는다.

## 자동 검사 결과

| 검사                         | 대상·범위                                                                         | 결과           | 실행 기록  |
| ---------------------------- | --------------------------------------------------------------------------------- | -------------- | ---------- |
| axe                          | 주요 11개 화면 × 모바일 390px·데스크톱 1280px                                     | 통과 (22/22)   | 2026-09-13 |
| 실제 키 입력 E2E             | 스킵 링크, 모바일 전체 악기 Dialog, 관리자 상품 Dialog, 모바일·데스크톱 구매 완료 | 통과 (5/5)     | 2026-09-13 |
| 공개 화면 가로 넘침·리플로우 | 사이트맵 공개 경로와 `/cart`, `/login`, `/support` × 6개 화면 폭                  | 통과 (6/6)     | 2026-09-13 |
| 전체 Playwright E2E          | 기능·보안·SEO·접근성·리플로우 회귀 전체                                           | 통과 (116/116) | 2026-09-13 |

axe 대상은 홈, 목록, 단일 상세, 악보집 상세, 밴드세트 상세, 장바구니, 결제, 완료, 로그인, 보관함, 관리자 악보 목록이다. serious·critical 위반은 0건이며 axe 규칙을 비활성화하지 않았다.

자동 키보드 검사의 범위는 다음과 같다.

- 첫 `Tab`에서 본문 바로가기 링크에 초점이 가고, `Enter` 뒤 `main#main`으로 이동한다.
- 모바일 전체 악기 Dialog는 정방향·역방향 `Tab` 순환 중 초점이 내부에 머물며, `Escape` 뒤 열기 버튼으로 초점이 돌아간다.
- 관리자 상품 Dialog는 키보드로 열었을 때 초기 초점이 내부에 있고, `Escape` 뒤 열기 버튼으로 초점이 돌아간다. 관리자 Dialog의 전체 `Tab` 순환은 자동 검사 범위에 포함되지 않았다.
- 로그인 상태를 미리 구성한 사용자가 모바일 390px과 데스크톱 1280px에서 홈 → 검색 → 상세 → 장바구니 → 결제 → 완료 → 보관함을 마우스 없이 완주한다.

추가 E2E는 포인트 보정 안내가 `role="status"`로 노출되는지, 관리자 상품 폼 오류가 `aria-invalid`와 `aria-describedby`로 연결되는지, 환불 사유 미선택·기타 사유 입력 상태에서 확정 버튼이 올바르게 비활성화되는지 확인한다. 이는 실제 스크린리더 음성 출력 확인과는 구분한다.
