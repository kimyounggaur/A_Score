## 측정 환경과 방법

- 점검일: 2026-09-13
- 대상: `next build` 뒤 `next start`로 실행한 로컬 프로덕션 빌드
- 도구: Lighthouse 13.4.1, Headless Chrome, 모바일 form factor와 기본 throttling
- URL: 홈 `/`, 대표 단일 악보 `/scores/1001`
- 표본: URL별 새 브라우저 프로필로 3회 순차 실행하고 중앙값 사용
- 작업본: 아직 커밋하지 않은 로컬 Stage B 작업본

예비 실행은 시스템의 다른 중량 작업과 겹쳐 TBT 편차가 컸다. 중량 작업을 종료하고 새 프로필로 전 6회를 다시 실행했으며, 아래에는 재측정한 유효 JSON만 기록한다. Windows에서 Chrome 임시 프로필을 지우는 과정의 `EPERM`으로 CLI가 보고서 생성 뒤 종료 코드 1을 반환했지만, 6개 JSON은 모두 완전하게 생성되어 파싱과 감사 결과를 확인했다. 보고서는 저장소가 아닌 `%TEMP%/scorestore-lh3-{home|detail}-final-{1..3}.json`에 보관했다.

## 초기 JavaScript 측정

Next.js 16 빌드 출력은 라우트별 First Load JS 표를 제공하지 않았다. 따라서 최종 `next start` HTML에 실제 포함된 modern 외부 `<script src>` URL을 중복 제거하고, `noModule` 스크립트는 제외한 뒤 `curl --compressed`의 `size_download`를 합산했다. 값은 1KB를 1,000B로 보는 decimal byte이며 HTML과 지연 청크는 포함하지 않는다.

| 날짜       | 경로                           | script 수 | 초기 JS gzip | 180,000B 이하 |

| 2026-09-13 | `/`                            |        11 |     178,641B |     통과      |
